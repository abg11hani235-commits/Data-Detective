# Data Detective — Sandbox Security Architecture & Hardening Specification

> **Notice**: No security model is 100% impenetrable. This document defines the exact defensive boundaries, threat models, verified security controls, container specifications, and known limitations enforced by the Data Detective execution engine.

---

## 1. Current Isolation Model

Data Detective adopts a multi-layered defense-in-depth model for executing untrusted, LLM-generated Python analysis code:

```text
Generated Python Code
        ↓
[Layer 1: Static AST Security Analysis]
  - Module Allowlist Enforcement
  - Dunder & Reflection Blocking
  - Path Traversal & OS Subprocess Disallowance
        ↓
[Layer 2: Environment Scrubbing & Runtime Sanitization]
  - os.environ completely cleared
  - Dangerous os module attributes deleted (system, popen, spawn, fork)
        ↓
[Layer 3: Execution Boundary]
  - Primary Local: Restricted Child Process in isolated temporary directory
  - Production Container: Rootless Docker Container (offline, read-only rootfs)
        ↓
[Layer 4: Resource & Output Constraints]
  - Wall-clock timeout (default: 15s)
  - Code size limit (50 KB)
  - Stdout / Stderr ceiling (256 KB)
  - Output contract verification (output/results.json <= 5 MB)
```

---

## 2. Threat Model

The primary threat vector is untrusted code generated by language models in response to user natural-language queries. Potential threats include:

| Threat | Attack Scenario | Mitigation in Data Detective |
|---|---|---|
| **Data Exfiltration / SSRF** | Code attempts to use `requests`, `urllib`, or `socket` to send data to an external server. | Blocked at AST level (`ALLOWED_MODULES`), stripped environment, and `--network none` in container mode. |
| **Arbitrary Command Execution** | Code invokes `os.system()`, `subprocess.Popen()`, `os.popen()`, or shell commands. | Blocked at AST level, runtime `os` attribute scrubbing, dropped capabilities (`--cap-drop=ALL`). |
| **Filesystem Traversal / Arbitrary File Overwrite** | Code attempts `open('../../.env')` or writes outside the workspace. | AST validates all `open()` and pandas `to_*()` arguments; rejects `..`, absolute paths, drive letters; restricts writes strictly to `output/`. |
| **Reflection & Dunder Escape** | Code attempts `().__class__.__base__.__subclasses__()` or `globals()`. | AST forbids all dunder traversal (`__subclasses__`, `__mro__`, `__builtins__`, etc.) and introspection builtins (`getattr`, `setattr`, `globals`, `locals`, `vars`, `dir`). |
| **Denial of Service (CPU / Memory Exhaustion)** | Infinite loops (`while True:`) or huge memory allocations. | Asynchronous `asyncio.wait_for` timeout (15s default), process termination (`proc.kill()`), `--cpus=1.0`, `--memory=512m`, `--pids-limit=64`. |
| **Output / Bomb Flooding** | Printing gigabytes to stdout/stderr or writing massive JSON. | `MAX_STDOUT_BYTES` (256 KB) truncation, `MAX_OUTPUT_SIZE_BYTES` (5 MB) file size enforcement. |

## 3. Blocked Capabilities & Static AST Rules

### Allowed Modules
Only pure data-science and computation packages are whitelisted:
- `pandas` / `pd`
- `numpy` / `np`
- `plotly` (and its submodules `express`, `graph_objects`, `subplots`)
- `scipy`, `scipy.stats`
- `statistics`
- `datetime`, `date`, `time`
- `math`
- `json`

All other module imports (such as `os`, `sys`, `subprocess`, `socket`, `requests`, `urllib`, `pathlib`, `shutil`, `importlib`) immediately trigger a **Security Policy Violation** before any process is spawned.

### Forbidden Built-ins & Introspection
The following built-ins are prohibited in AST parsing:
- `eval`, `exec`, `compile`, `__import__`
- `getattr`, `setattr`, `delattr`
- `globals`, `locals`, `vars`, `dir`, `help`
- `breakpoint`, `exit`, `quit`, `input`
- `memoryview`, `bytearray`

### Forbidden Attributes & Dunder Lookups
- `__subclasses__`, `__bases__`, `__base__`, `__class__`
- `__globals__`, `__dict__`, `__mro__`, `__code__`
- `__closure__`, `__func__`, `__self__`, `__module__`
- `environ`, `getenv`, `system`, `popen`, `spawn`, `fork`, `execv`, `execve`

## 4. Container Execution Mode (Docker)

For production deployments, Data Detective includes `DockerSandboxRunner` (`app/sandbox/docker_runner.py`), which executes code within an isolated container when Docker is available:

```bash
docker run --rm \
  --network none \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --user 1000:1000 \
  --cap-drop=ALL \
  --cpus 1.0 \
  --memory 512m \
  --pids-limit 64 \
  -v /ephemeral/sandbox_dir:/workspace:rw \
  -w /workspace \
  python:3.11-slim python analysis.py
```

### Container Isolation Properties
1. **Network**: `--network none` ensures zero egress or ingress network traffic.
2. **Root Filesystem**: `--read-only` prevents any modification to the container operating system.
3. **Capabilities**: `--cap-drop=ALL` strips all Linux kernel capabilities.
4. **Resources**: Capped to 1.0 CPU core, 512 MB RAM, and 64 max processes (prevents fork bombs).
5. **Temporary Ephemeral Mount**: Workspace is mounted only for the duration of the analysis and purged immediately upon completion.

## 6. Remaining Limitations & Honest Disclosure

1. **Subprocess Isolation on Windows / Dev**:
   - In development environments without an active Docker daemon, execution runs in an OS child process (`sys.executable`).
   - While protected by AST allowlisting, path inspection, and environment scrubbing, a subprocess is **not a hardware or kernel virtualization boundary**. It does not provide kernel-level cgroups on Windows hosts.
2. **Side-Channel Timing**:
   - Complex nested loops that do not crash can consume CPU up to the 15-second timeout.
3. **Memory Limits in Subprocess Mode**:
   - In subprocess mode without cgroups, a memory allocation is bounded only by host RAM until it hits OS allocation failure or triggers timeout. Production deployments **must** enable `SANDBOX_BACKEND=docker` or run in a Kubernetes container with resource limits.
4. **Third-Party C-Extensions**:
   - `numpy` and `pandas` link to native C/Fortran libraries. While memory-safe in standard analytical operations, internal native library bugs (e.g. buffer overflows in C extensions) could theoretically exist in unpatched versions.

## 7. Development Mode vs. Production Mode

| Capability | Development Mode (`SANDBOX_BACKEND=subprocess`) | Production Mode (`SANDBOX_BACKEND=docker`) |
|---|---|---|
| **AST Code Validation** | Enabled | Enabled |
| **Environment Scrubbing** | Enabled | Enabled |
| **Timeout Enforcement** | Enabled (asyncio kill) | Enabled (asyncio + container kill) |
| **Code Size Limits** | Enabled (50 KB) | Enabled (50 KB) |
| **Output Limits** | Enabled (5 MB) | Enabled (5 MB) |
| **Network Isolation** | Software AST block | Kernel-level (`--network none`) |
| **Filesystem Isolation** | Temporary folder + path checks | Read-only rootfs + isolated volume |
| **Memory Cgroup Boundary** | Host OS dependent | Hard 512 MB limit |
| **Capability Dropping** | Attribute level | Kernel-level (`--cap-drop=ALL`) |
